# سند مشخصات پروژه — استودیو نقاشی فندوقی 🌰

> تنظیم‌شده توسط: مدیر ارشد پروژه (برای دستیار برنامه‌نویس B)
> تاریخ: ۱۷ مرداد ۱۴۰۵

## ۱. هدف پروژه
یک وب‌اپ نقاشی مخصوص کودکان، کاملاً فارسی و راست‌به‌چپ، بدون نیاز به نصب یا بک‌اند.
بچه‌ها باید بتوانند با ابزارهای حرفه‌ای و براش‌های جادویی نقاشی بکشند،
شاهکارهایشان را در آلبوم ذخیره کنند و با آموزش‌های قدم‌به‌قدم، ترفندهای نقاشی یاد بگیرند.

## ۲. الزامات کارکردی (Functional Requirements)

| کد | الزام |
|----|-------|
| FR-1 | بوم نقاشی (Canvas) سفید، واکنش‌گرا به اندازهٔ صفحه، پشتیبانی لمس و موس، مقیاس صحیح در نمایشگرهای رتینا |
| FR-2 | ابزارهای حرفه‌ای: قلم‌مو، مداد، پاک‌کن، اسپری، سطل رنگ (پر کردن ناحیه)، خط، مستطیل، بیضی، مثلث، ستاره |
| FR-3 | براش‌های جادویی: رنگین‌کمان، برق جادویی، نئون (درخشان)، مهر قلب، مهر ستاره، مهر گل، مهر پروانه، مهر شکلک خندان |
| FR-4 | پالت ۱۲ رنگ ثابت + انتخاب رنگ دلخواه + تنظیم اندازهٔ قلم (۲ تا ۶۴) |
| FR-5 | تاریخچهٔ Undo/Redo (حداقل ۲۰ قدم) + پاک‌کردن کل بوم |
| FR-6 | ذخیره در آلبوم با نام انتخابی، نمایش شبکه‌ای کارت‌ها، نمایش بزرگ، دانلود PNG، ادامهٔ نقاشی از روی نقاشی ذخیره‌شده، حذف |
| FR-7 | ذخیرهٔ خودکار پیش‌نویس: نقاشی نیمه‌کاره با رفرش صفحه از بین نرود و در بازگشت برگردد |
| FR-8 | بخش آموزش: حداقل ۵ آموزش قدم‌به‌قدم با تصویر (SVG) برای هر قدم + نوار پیشرفت + ذخیرهٔ پیشرفت یادگیری |
| FR-9 | بخش ترفندها: حداقل ۶ ترفند کاربردی برای راحت‌تر نقاشی‌کشیدن |
| FR-10 | جلوه‌های صوتی سرگرم‌کننده با امکان قطع/وصل صدا (وضعیت ذخیره شود) |
| FR-11 | میان‌برهای صفحه‌کلید: Ctrl+Z / Ctrl+Shift+Z و تغییر اندازه با کلیدهای [ و ] |
| FR-12 | پیام‌های راهنما و تشویقی فارسی (Toast) در تمام عملیات مهم |

## ۳. الزامات غیرکارکردی (Non-Functional Requirements)

| کد | الزام |
|----|-------|
| NFR-1 | رابط کاربری فارسی RTL، فونت وزیرمتن با فونت جایگزین سیستمی |
| NFR-2 | کاملاً ریسپانسیو: دسکتاپ (نوار ابزار کنار بوم) و موبایل/تبلت (نوار ابزار افقی) |
| NFR-3 | دسترس‌پذیری: برچسب‌های aria، فوکوس واضح، دکمه‌های لمسی حداقل ۴۴px |
| NFR-4 | امنیت: ورودی کاربر (نام نقاشی) هرگز با innerHTML رندر نشود؛ اعتبارسنجی رکوردهای ذخیره‌شده |
| NFR-5 | ذخیره‌سازی: فقط localStorage، مدیریت سقف حجم (quota) با پیام خطای دوستانه |
| NFR-6 | بدون وابستگی build؛ فقط HTML/CSS/JS خالص؛ اجرا با باز کردن فایل یا هر سرور استاتیک |
| NFR-7 | پرهیز از حرکت‌های سنگین برای کاربران حساس: پشتیبانی prefers-reduced-motion |

## ۴. ساختار تحویلی
```
index.html          — صفحهٔ اصلی و تمام مارک‌آپ
css/style.css       — تمام استایل‌ها
js/storage-core.js  — هستهٔ ذخیره‌سازی (خالص، قابل تست)
js/utils.js         — ابزارهای عمومی (خالص)
js/sound.js         — جلوه‌های صوتی Web Audio
js/engine.js        — موتور نقاشی (بوم، ابزارها، تاریخچه)
js/album.js         — آلبوم شاهکارها
js/tutorials.js     — دادهٔ آموزش‌ها و ترفندها + رندر
js/app.js           — اتصال همهٔ ماژول‌ها و رابط کاربری
tests/checks.mjs    — تست‌های خودکار مدیر
README.md           — مستندات
```

## ۵. معیار پذیرش (Acceptance Criteria)
- همهٔ FRها با تست دستی مدیر پاس شوند.
- تست‌های خودکار (syntax + منطق خالص + داده‌های آموزش + ساختار HTML/CSS) سبز باشند.
- هیچ خطای کنسولی در مرورگر هنگام استفادهٔ عادی وجود نداشته باشد.
